# SevynOS Layout Manifest

**Status:** draft for Kevon's call · **Date:** 2026-11-27, extended 2026-11-28 · **Base:** SevynOS main `fe0277ba`, Genesis main `fcdf9c54`
**What this is:** SevynOS's own structured design framework for windows, top bar, popup menus, and dialog boxes — inspired by Apple's proven premium designs, with SevynOS's own numbers. Not a macOS copy.
**Machine-readable tokens:** [tokens.json](tokens.json) · **Mockups:** [mockups/](mockups/) · **Sources & deferred decisions:** [NOTES.md](NOTES.md)

Every number below is one of three things: **measured** from the current tree (file + line cited), **verified** from Apple (source cited), or a **proposal** awaiting Kevon's call. Nothing is invented silently.

---

## 1. Principles

1. **Own identity first.** Dark-first cosmic desktop, violet accent, neutral chrome. Apple is the reference for discipline, never the look to clone.
2. **One spacing scale everywhere.** The 4pt scale (`0 4 8 12 16 20 24 32 48`) governs every surface; no surface invents its own gaps.
3. **Every surface has one layout.** A window header, a menu row, a dialog button row — each has exactly one geometry, defined here, used everywhere.
4. **States are part of the layout.** Active/inactive, hover, pressed, disabled, focused — each state is specified with the layout, not added later.
5. **Light and dark are both first-class.** Every color token is a light/dark pair. Dark-first today is the current state, not the spec.
6. **Accent is a signal, not a theme.** One user-chosen accent, applied only where it means something (selection, focus, active controls). Chrome and body text stay neutral.
7. **Pointer-first, keyboard-complete.** Every pointer action has a keyboard path; every menu item has a shortcut where one exists.

## 3a. Desktop icons

The grid already exists in `DesktopIcons.tsx` (measured, main `fe0277ba`): `desktopColumns(surfaceWidth)` = floor((width − 48) / (104 + 18)), tiles 104×92, gaps 18/16, left margin 24, top 22, icon 48×48 radius 8, monogram 24 bold white, label 12 white. What it does not have: any size choice (one size — medium), and no selection state. The manifest sizes the grid and adds both.

| Rule               | SevynOS                                                                                                                                                                                                                | Rationale                                                                |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Grid               | columns = floor((surfaceWidth − 48) / pitch), row-major, left-to-right, top-to-bottom (measured, kept)                                                                                                                 | The grid already exists — the manifest sizes it, it does not redesign it |
| Margins            | 24 left, 22 top (measured, kept); 16 bottom clearance above the dock                                                                                                                                                   |                                                                          |
| Sizes              | **S:** 80×72 tile, 36 icon r6, label 11 · **M:** 104×92 tile, 48 icon r8, label 12 (today, measured) · **L:** 128×112 tile, 64 icon r10, label 13                                                                      | M is today's measured geometry; S and L scale from it on the 4pt grid    |
| Pitch (tile + gap) | S 94×84 · M 122×108 · L 152×132                                                                                                                                                                                        |                                                                          |
| Gaps (x / y)       | S 14/12 · M 18/16 · L 24/20                                                                                                                                                                                            |                                                                          |
| Icon               | kind-color tile + white monogram (measured, kept); radius by size (6/8/10)                                                                                                                                             | The shell has no vector icons — the tile + monogram is the icon          |
| Label              | white, centered, ≤2 lines, **text shadow `0 1px 3px rgba(0,0,0,0.45)`** (NEW — the shadow is what keeps white labels readable on a light photo wallpaper; found in the mockup review)                                  |                                                                          |

### 5a. System menu (SevynOS logo menu)

The system menu is a popup menu with fixed contents — it uses the standard menu geometry, no special-case sizing. It is the Apple-menu model: the SevynOS mark at the top-left is the trigger, and the power actions live here now that Power has left the top bar (tweak 4).

| Rule     | SevynOS                                                                                                                                                                                                     | Rationale                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Trigger  | the SevynOS mark at the top-left is a pressable (CHANGE — today it is static `<Text>` in `Shell.tsx`; the tray's Power pill was the only pressable)                                                         | The logo is the system menu — the macOS Apple-menu model |

## 7. Accent system

Same six accents as Tokrah — same family, same discipline: **neutral chrome + one accent**. (Tokrah: `utils/accent.ts`; SevynOS adopts its light/dark fills and text variants verbatim.)

| Accent               | Light fill | Dark fill | Text on light surface | Label on fill (light) | Label on fill (dark) |
| -------------------- | ---------- | --------- | --------------------- | --------------------- | -------------------- |
| Neutral              | `#14141A`  | `#FAFAFA` | `#14141A`             | `#FFFFFF`             | `#14141A`            |
| **Violet (default)** | `#5B5BD6`  | `#8B8BFF` | `#5B5BD6`             | `#FFFFFF`             | `#14141A`            |
| Coral                | `#FF6B4A`  | `#FF8563` | `#B24B34`             | `#000000`             | `#14141A`            |
| Teal                 | `#0EA5A5`  | `#2EC4C4` | `#0A7373`             | `#000000`             | `#14141A`            |
| Rose                 | `#E84A7A`  | `#F472A0` | `#A23455`             | `#000000`             | `#14141A`            |
| Sky                  | `#0284C7`  | `#38BDF8` | `#015C8B`             | `#000000`             | `#14141A`            |

**Verified contrast (computed against SevynOS surfaces, 2026-11-27):** accent text on light surface — all pass 4.5:1 (worst coral 5.32, violet 5.37); accent fill on dark surface — all pass 4.5:1 (worst violet 5.06 on `#1F2937`); label on fill — light mode white passes only violet (5.37) and neutral (18.35), black passes coral/teal/rose/sky; dark mode ink `#14141A` passes all (worst violet 6.32), white fails all (1.04–2.90). The onFill rule is therefore: **light mode — white on violet/neutral, true black `#000000` elsewhere; dark mode — ink `#14141A` always.** (Light-mode black is true `#000000`, not ink: ink on sky light is 4.48, true black 5.13 — the same edge Tokrah measured.)

**Where accent applies:** selection highlight, focus rings, active controls, toggles/switches, progress, links, AI button.
**Where accent NEVER applies:** window chrome, body text, app icon colors, wallpaper. The discipline is the point: accent is a signal, not a theme.

**Where SevynOS deliberately differs from Tokrah:** Tokrah's default is Neutral (the login look); SevynOS's default is **Violet** — it is already the SevynOS accent (AI button, current highlights) and the OS has no login screen to keep neutral. Tokrah applies the accent inside one app; SevynOS applies it system-wide, across shell and apps. The palette and the contrast math are shared; the default and the scope are not.

**Behavior:** the picker lives in Settings → Appearance next to the mode switch; one Appearance section, instant apply, no restart; the choice persists system-wide (settings store). **Per-app accent override: deferred** — no v1 override; decision 7, decided 2026-11-28.

**Mockup:** [mockup-accent-strip.png](mockups/mockup-accent-strip.png) — one window header + menu row + dialog button row in all six accents, both modes, on one image. Plus [mockup-windows-coral-dark.png](mockups/mockup-windows-coral-dark.png) — the window surface in Coral (dark), to show the system in context.

## 9. Wallpaper & Background — instant preview

**Current behavior (code-proven — the gap this section closes):** tapping a wallpaper style writes the setting immediately (`sevyn settings set wallpaperStyle X`, `Settings.tsx:569`), but the shell only re-reads the setting on re-render — "picking a new style applies when Settings closes" (`Wallpaper.tsx` header; the UI tells the user "Applies when Settings closes"). The picker is text buttons (120×36) + color swatches (44×44) inside a fullscreen Settings window, so the desktop is invisible while choosing. There are no thumbnails, no hover preview, and no live feedback at all.

**Manifest behavior — the core rule:** picking a wallpaper applies it to the live desktop **immediately** — no Apply button, no confirm step, no restart. The picker shows the live desktop behind it, so what you see is what you get.

## 11. Decisions (all 9 decided)

1. **Window-controls side — DECIDED: RIGHT (Kevon, 2026-11-28 ~02:30 EST).** Left was the recommendation (macOS muscle memory, frees the right end for per-app toolbar actions) but costs a host-constant change (`kCloseZoneWidth` moves) plus the four custom title bars and the template. Right costs nothing and matches Windows users. Mockup: [mockup-decision-controls.png](mockups/mockup-decision-controls.png).
2. **Top-bar height — DECIDED: 32 (Kevon, 2026-11-28 ~02:33 EST).** 32 reclaims 16px of vertical space and matches macOS proportions; it requires shrinking pills/buttons to 28 and retouching m9-check coordinates — **Power is gone from the bar, so the check must open the SevynOS logo menu at the top-left and pick the power item instead** (the old note "the check taps Power at 1872,24" is dead); the control icon sits at the bar's right end (~1890,16 at 1920×1080) and must not be mistaken for Power. 48 needs no work but wastes space and reads non-macOS. Mockup: [mockup-decision-topbar.png](mockups/mockup-decision-topbar.png).
3. **App menus in the top bar — DECIDED: build with the polish (Kevon, 2026-11-28 ~02:37 EST).** Building menus is a feature (app menu registry, per-app File/Edit/View, shortcuts) and it now lands in the polish pass, riding with the top-bar surface. The draft recommended reserve-now-build-later; Kevon chose to build it now.
4. **Dialog button order — DECIDED: Apple (Cancel leading, default trailing) (Kevon, 2026-11-28 ~02:40 EST).** It matches the HIG and every macOS user's muscle memory; the migration is mechanical across the four inline confirms. Cost: users who learned the current order re-learn it.
5. **Wallpaper mode-switch — DECIDED: auto-switch with fallback (Kevon, 2026-11-28 ~02:42 EST).** Auto-switch keeps the mode coherent (a dark wallpaper under light chrome breaks the mode); keep-pick never surprises the user. The wallpaper is part of the mode's readability, so it follows the mode.
6. **Wallpaper hover-preview — DECIDED: hover-preview (Kevon, 2026-11-28 ~02:43 EST).** It is the macOS behavior and costs ~nothing extra once live-apply exists (same repaint path).
7. **Per-app accent/mode override — DECIDED: deferred (Kevon, 2026-11-28 ~02:44 EST).** No v1 override; system-wide only. Revisit if an app (e.g. a pro tool) ever needs its own mode.
8. **Window corner radius — DECIDED: compositor rounds the windows (Kevon, 2026-11-28 ~02:46 EST).** True rounded toplevels with clean shadows; the compositor gains rounded-toplevel support as part of the polish build. The renderer-drawn fallback (faked corners, square window underneath) is not used. The manifest sets 10.
9. **Top-bar glass in light mode — DECIDED: mode-adapted (Kevon, 2026-11-28 ~03:09 EST, by confirming the mockups).** Dark mode takes the dock's exact glass values (fill `#ffffff1f`, edge `#ffffff14`, highlight `#ffffff40`, shade `#00000033`). Light mode takes the same technique with adapted opacities — light fill white 70% (`#ffffffb3`), edge black 8% hairline (`#00000014`), top highlight pure white, shade `#00000033` — so the bar reads over light wallpaper. The literal option (the dock's exact four values in both modes) was rejected: the light bar is a ghost over light wallpaper. The mockups render the decided version.
